# Nuff 첫 사용 흐름

제품 결정: 2026-09-25. 카카오 연결을 가입 조건으로 만들지 않는다.

## 사용자가 하는 일

1. 앱 첫 실행에서 소개를 읽고 시작한다.
2. 이메일·비밀번호로 Nuff 계정을 만들거나 기존 계정에 로그인한다.
3. `공유 준비하기`를 누르고 iOS 공유창에서 Nuff를 선택한다.
4. 연결 완료 후 Safari·YouTube 등에서 실제 링크를 공유 → Nuff로 보낸다.
5. 저장 완료 메시지를 확인하고 앱의 보관함에서 링크를 연다.
6. 필요할 때만 설정 → 수집 채널 추가 → 카카오톡을 연결한다. DM·디스코드는 아직 미구현이다.

웹에서는 같은 이메일 계정으로 로그인해 보관함을 이용한다. 채널 추가는 계정 메뉴 안의 접힌 선택 항목이다. 이미 연결된 카카오에는 연결 완료 상태를 표시한다. 예시 자료는 사용자가 명시적으로 선택할 때만 표시한다.

## 현재 개인 개발 빌드의 공유 연결

앱과 Share Extension은 서로 다른 저장 공간을 사용한다. 현재 빌드는 App Groups로 로그인 세션을 공유하지 않으므로, 최초 한 번 공유창을 통해 단기 연결 코드를 전달한다.

- 로그인된 앱이 `POST /auth/device-code`로 10분짜리 일회용 코드를 발급받는다.
- 공유창에 `NUFF-CONNECT:<code>`를 전달하고 사용자가 Nuff를 선택한다.
- 확장은 `POST /auth/pair`로 자기 세션을 발급받는다. 설정 입력은 콘텐츠로 저장하지 않는다.
- 사용자가 연결 완료를 누르면 앱은 해당 계정의 공유 준비 상태를 기록한다.
- 이후 링크는 확장의 세션으로 `POST /captures/shortcut`에 전송한다.
- 앱과 웹은 각자의 로그인 세션으로 `GET /captures`에서 동일한 계정의 보관함을 읽는다.

앱에서 로그아웃하는 것만으로 확장의 기존 세션까지 지워지지는 않는다. 계정을 바꾸면 새 계정에서 `공유 준비하기`로 다시 연결해야 한다. 상용화 전에 App Groups/Keychain을 이용한 세션 공유·로그아웃 동기화를 검토한다. 현재 코드 전달 방식에서 다른 공유 대상을 선택하지 않도록 Nuff 선택을 안내한다.

## 선택 채널의 계정 보호

- 카카오 연결 입력은 카카오 identity가 있는 원본 계정만 허용한다.
- 이미 다른 이메일 계정에 속한 카카오는 자동 병합하지 않는다.
- 잘못 입력한 공유 코드는 카카오 연결 과정에서 소비하거나 다른 계정과 합치지 않는다.
- 이미 확인된 이메일에 임의의 확인 코드를 보내도 로그인 세션을 발급하지 않는다.

## 검증 상태

- 서버 테스트 18개 통과: 카카오 없는 계정의 공유 연결, 설정 단계에서 콘텐츠 미생성, 앱/확장 계정 일치, 사용자 분리, 잘못된 계정 병합 차단 포함.
- TypeScript 검사, 웹 빌드, iPhone 대상 빌드 통과.
- 웹에서 기존 보관함 8개와 접힌 선택 채널 메뉴 확인.
- 연결된 개발용 iPhone에 앱 업데이트 설치 완료.
- 이번 버전의 실제 iPhone 공유창 완료 콜백 및 외부 앱에서 첫 링크 저장은 사용자 확인 필요. 빌드·설치 성공과 실제 기기 사용 성공은 구분한다.
